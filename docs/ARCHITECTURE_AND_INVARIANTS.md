# 아키텍처 의존성 및 절대 불변 규칙

기준: 2026-11-23, `SAVE_VERSION` 15. 기능을 넣을 때 여기의 불변 조건을 먼저 본다. 수치 원본은 `docs/GAME_DESIGN_SPEC.md`.

---

## 1. 데이터가 흐르는 방향

```
data (generals, bonds, stages, gear, meta)
        ↓ 읽기 전용
engine (순수 함수)  ←── workers/counter.worker.ts
        ↓
store/gameStore.ts  ← localStorage `oath-banner-save`
        ↓            ← cloud/ (같은 SaveData 모양)
pages, components   화면과 입력만
```

- `src/engine`은 `localStorage`, `window`, `document`, React를 모른다. 시각이 필요하면 `now` 인자로 받는다. 이 순수함을 깨면 Web Worker의 맞춤 편성이 같이 죽는다.
- 전투 수식은 `simulateBattle` 한 곳이다. 화면은 이미 만들어진 `BattleEvent[]`를 재생한다.
- 보상·해금·행군·내정 적용은 `gameStore`다. `battle.ts`를 고친다고 금화 공식이 바뀌지 않고, 그 반대도 같다.
- 저장되는 것은 `pickSave()` 필드와 `entered`, `view`뿐이다. 전투 로그, 모의전 설정, 모의전 기록, `focusStage`는 새로고침하면 사라진다. 보상은 전투 화면을 열기 **전에** 저장 본문에 들어간다.

화면 (`App.tsx`): 타이틀 → 원정 `campaign` · 편성 `formation` · 등용 `recruit` · 장수록 `roster` · 도전 `challenge` · 전투 `battle`. 가로(높이 500px 이하)는 `LandShell`이 같은 스토어를 다른 배치로 그린다. 세로는 기존 페이지. 규칙은 한 벌이다.

## 2. 저장

키 `oath-banner-save`. Zustand `persist` + `saveData.ts`.

`SaveData` 필드: `started`, `gold`, `roster`, `formation`, `cleared`, `fought`, `totalPulls`, `conquestBest`, `conquestFailFloor`, `freePulls`, `freeGrantDay`, `attendDay`, `attendStreak`, `presets`, `gear`, `wounds`, `marches`, `castles`, `threats`, `lastThreatAt`, `decreeClaimWeek`.

필드를 추가·이름 변경·의미 변경하면 아래를 **같이** 고친다.

1. `SAVE_VERSION`을 1 올린다. 7은 비어 있다 (6 다음이 8). 번호를 재사용하지 않는다.
2. `migrateSave`에 `version < N` 분기를 넣는다. 끝은 항상 `sanitizeSave`.
3. `sanitizeSave` / 해당 `sanitize*`에서 범위 밖 값을 자른다. 알 수 없는 장수·장비·스테이지 id는 버린다.
4. `pickSave`와 `saveSignature`에 필드를 넣는다. 빠지면 클라우드 동기화가 그 변경을 못 보거나, 반대로 항상 충돌한다.
5. `freshSave` 기본값을 준다.
6. 예전 저장을 한 번 로드해 금화·편성·클리어가 유지되는지 본다.

이미 있는 마이그레이션 (지우거나 순서를 바꾸지 않는다):

| 버전 | 하는 일 |
|---|---|
| &lt; 2 | 3칸 편성(`vice`)을 6칸(`vice1`)으로 |
| &lt; 3 | `promote: 0` |
| &lt; 4 | 옛 일일 등용 필드 |
| &lt; 5 | 편성 포인트·프리셋 |
| &lt; 6 | 포인트 × 10을 금화에 더하고 `points` 삭제 |
| &lt; 8 | `cleared`가 있는데 `fought`가 없으면 `fought`로 복사 |
| &lt; 9 | 무료 등용·출석. `recruitDay` / `recruitUsed` 삭제 |
| &lt; 10 | `gear: {}` |
| &lt; 11 | 장비 `count: 1` |
| 12~14 | 별도 분기 없이 `sanitizeSave`가 빈 `wounds` / `marches` / `castles`를 채운다 |
| &lt; 15 | `threats` / `lastThreatAt` / `decreeClaimWeek` 기본값 |

점령 성 소급은 `migrate`가 아니라 실행 중 `ensureCastles`다. `since = 지금`이라 과거분 금화가 생기지 않는다. 여기를 점령 시각 추정으로 바꾸면 옛 저장에 금화가 몰린다.

`sanitize`가 지키는 범위: 레벨은 표시 등급 상한(R50·SR100·SSR150), 돌파 0~5, 품계 0~`maxPromote`(R는 2), 금화 0~10억, 성 레벨 1~5, 장비 레벨 1~10 · 강화 0~5 · 복제 1~18, 행군 최대 3, 위협 최대 3, 프리셋 최대 6. 편성은 보유 장수만, 전체에서 id 중복 제거. 옛 `vice` 칸은 `vice1`로 읽는다.

클라우드 (`src/cloud/reconcile.ts`): 원격 없음 → 업로드, 시그니처 동일 → 유지, 로컬이 새 게임 그대로 → 다운로드, 아니면 충돌. `applySaveState`는 저장 본문만 바꾸고 전투 화면은 닫는다.

`partialize`: 전투 화면에서 새로고침하면 view를 원정(원정 전투) 또는 도전(모의전·토벌)으로 저장한다. 전투 로그는 없다. 보상을 전투 종료 버튼으로 옮기면 새로고침에 보상이 사라지거나 두 번 나간다.

| `siege.ts` | 출정 잠금, 부상 키, 회복 시간, 10% 출정 제한, 행군 스냅샷 |

편성 편집기는 `FormationEditor.tsx` 하나다. 편성 탭·원정·모의전이 같이 쓴다. 여기만 고치고 한 화면만 보면 다른 화면이 깨진다.

## 4. 절대 불변 조건

1. **시드가 같으면 전투가 같다.** `simulateBattle`은 프로필, 시드, 시작 병력 비율, 게이지 보너스, `mulberry32` 호출 순서만으로 결정된다. 시각·`Math.random`·DOM을 전투 루프에 넣지 않는다. 이벤트 중간에 난수를 추가하면 그 뒤의 명중·연쇄·표적이 전부 달라진다.
2. **라이브 전투 시드는 저장하지 않는다.** 원정·모의전·토벌은 계산 직후 상태만 확정한다. 로드할 때 전투를 다시 굴리지 않는다. 다시 굴리면 새로고침마다 승패가 바뀐다.
3. **토벌 군단 구성은 층 번호로 고정**이다 (`층 × 7919 + 17`). 전투 난수와는 별개다. 같은 층을 편성만 바꿔 다시 칠 수 있어야 한다.
4. **맞춤 편성·100전 측정의 시드 표는 고정**이다. 시간을 시드에 섞지 않는다. 시간 예산(3초)은 시도 횟수에만 영향을 준다.
5. **수식은 `src/engine`에만 둔다.** 페이지·컴포넌트에 0.04, 1.25, 0.8, 연쇄 0.6, 발동 상한 0.7을 새로 적지 않는다. 보여 주는 글은 엔진이 돌려준 값을 쓴다.
6. **`engine`은 저장소를 모른다.** Worker가 같은 파일을 import한다.
7. **슬롯 순서 `주장, 부장, 부장, 참모, 보좌, 보좌`.** 참모 인덱스는 3. 적 `members`도 이 순서다.
8. **한 장수는 편성 전체에서 한 칸.** `assign`과 `sanitizeFormation`이 같이 지킨다. 한쪽만 풀지 않는다.
9. **주장 없는 부대는 출진하지 않는다.** 빈 연쇄 칸은 확률을 소모하지 않고 건너뛴다. 실패한 연쇄는 뒤 칸을 시도하지 않는다.
10. **명참모는 태생 지력 90이다.** 유효 지력(레벨·돌파·장비)으로 바꾸면 기존 참모 평가가 바뀐다. 발동률만 참모의 유효 지력을 쓴다 (`× 0.001`, 상한 0.70).
11. **시너지 단계는 최고 단계 하나.** 3명 보너스에 6명 보너스를 더하지 않는다. 여러 세력·여러 인연은 서로 더한다.
12. **성장 배율은 곱연산, 장비는 그 다음 합연산.** 레벨 `(1+(L-1)×0.04)`, 돌파 `(1+★×0.04)`. 품계는 배율 없이 상한만 연다(승급 시 레벨 리셋). 토벌 각인은 프로필에 별도 곱.
13. **원정 금화·경험치는 첫 점령 전에만.** 점령 후 재도전은 0. 첫 승리는 `reward.gold + firstClearGold`. 미점령 패배는 금화 20%·경험치 30% (반올림). 토벌 패배는 금화 10%·경험치 30%. 이 비율은 `gameStore`에 있다.
14. **장비 드랍은 승리만.** 원정 재도전이고 이미 있으면 40% (`Math.random`, 시드 고정 아님). 토벌은 승리 시 항상 `grantGear`.
15. **부상 키는 주장 id와 `c:성:인덱스`.** 편성 칸 번호로 바꾸면 칸을 바꿀 때마다 부상이 사라진다. 점령한 성 수비는 항상 만피로 시작하고 패배 부상을 남기지 않는다. 승리 시 그 성 수비 키는 삭제한다.
16. **출정 하한은 최대 병력의 10% 이상.** 회복은 타이머 없이 저장 시각으로 계산한다. 부대 3분, 수비 15분 (0%에서 100%).
17. **행군은 출발 스냅샷 + `eta`.** 동시 3개. 도착 전 편성 수정이 그 전투에 들어가면 안 된다. 전술비는 출발 때 확정이고 환불하지 않는다.
18. **내정 적립은 `since`와 상한 8시간.** 레벨·수비를 바꾸기 전에 정산한다. 돈이 없어 업그레이드가 실패하면 `since`를 건드리지 않는다. 소급 지급하지 않는다.
19. **토벌 개방 조건은 `cleared['4-3']`.** 8장 클리어로 바꾸려면 저장 호환(이미 4-3만 깬 계정)을 따로 정한다.
20. **등용 확률과 천장은 `gacha.ts` 한 곳.** 10연 900원은 무료를 전혀 안 썼을 때만. 무료가 섞이면 유료 횟수 × 100.
21. **무료 10회는 날짜가 바뀔 때 더한다.** 남은 횟수를 10으로 리셋하지 않는다. 출석을 하루 거르면 연속은 1부터다.
22. **외부 이미지 URL을 넣지 않는다.** SVG·CSS·이모지·lucide, 초상만 `public/portraits/*.webp`. 코에이 CG를 따라 그리지 않는다.
23. **장수 id는 `generals.json`이 원본.** 초상 Set, 스테이지 적 id, 인연 태그는 그 id와 맞아야 한다. id를 바꾸면 로스터·편성·프리셋·행군·수비에서 그 장수가 삭제된다 (`sanitize`).
24. **시그니처에 없는 저장 필드는 동기화되지 않는다.** 키 순서가 의미 있는 배열(`marches`, `formation`)의 정렬을 `saveSignature`에 멋대로 넣으면 같은 기록이 충돌로 보인다. 지금 정렬하는 것은 roster, cleared, fought, presets, gear뿐이다.

## 5. 의도적으로 나뉜 난수

| 무엇 | 난수 | 다시 돌리면 |
|---|---|---|
| 전투 이벤트 | 인자 시드 + `mulberry32` | 같은 시드면 같은 결과 |
| 원정·모의전·토벌의 전투 시드 | `randomSeed()` 1회, 미저장 | 같은 전투를 재현하지 않음. 보상은 이미 저장됨 |
| 토벌·모의전 **적 구성** | 층 번호 또는 모의전 시드 | 구성은 다시 같음 |
| 지원군 발생 | 행군 id 해시 | 그 행군 안에서는 고정. 행군 id에 시각이 들어 있어 다음 출정은 다름 |
| 날씨 | 30분 블록 해시 | 저장 불필요 |
| 등용, 장비 40% | `Math.random` | 재현 대상이 아님 |
| 맞춤 편성 탐색 변형 | `0x5eed + 장수 수` | 후보 비교 시드는 고정, 몇 번 시도할지는 3초 예산 |

전투 결정론을 "저장하면 같은 전투가 재생된다"로 해석하지 않는다. 결정론은 **함수 입력**에 대한 것이다.

## 6. 넣지 말아야 할 지름길

- 화면에 `atk * 3.2` 같은 미리보기 수식을 복사해 두지 않는다. `buildProfile` / `simulateBattle` 결과를 보여 준다.
- 스테이지 보상 숫자를 컴포넌트에 다시 적지 않는다. `STAGES`를 읽는다.
- 행군 중 부대의 현재 편성을 도착 때 다시 읽지 않는다. `March.units`만 쓴다.
- 점령 성 재수비에 부상 비율을 곱하지 않는다. 코드는 점령 후 `r = 1`이다.
- 워커에 React 상태나 `localStorage`를 넘기지 않는다. `CounterInput`은 직렬화되는 데이터만이다.
- 밸런스 숫자를 감으로 바꾸지 않는다. 자동 편성 덱이 일반 스테이지는 무난히, 장 보스는 60~90%, 시너지를 무시한 배치는 보스에서 크게 지게 두는 것이 기준이다 (`CLAUDE.md`).
